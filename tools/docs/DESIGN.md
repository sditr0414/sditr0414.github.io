# 포트폴리오 디자인 기준

> 2026-10-20: 승인된 수정본을 공개 사이트에 반영했습니다. 현재 디자인 원본은 `docs/app.css`이며 소개·프로젝트 카드와 상세 화면으로 구성합니다. 아래 16장 슬라이드 기준은 전환 전 기록입니다. 제출용 슬라이드 디자인은 별도 `portfolio-submission` 저장소에서 관리합니다.

## 화면 구성

기계·로봇 분야의 제작물과 구현 과정을 읽는 엔지니어 포트폴리오입니다. 네이비 표지와 흰색 본문, 실제 사진·회로도·실험 화면을 중심으로 구성합니다. 프로필과 학력·교육, 프로젝트 6개를 16장에 담습니다. 팀 전체 기능과 개인 담당 범위를 구분하며, 기술이나 성과를 장식용 수치로 추가하지 않습니다.

- 표지: 이름과 지원 분야, 소개, 프로젝트·실습에서 사용한 기술 순으로 배치합니다.
- 프로젝트 개요: 왼쪽에 자동 재생 시연, 오른쪽에 설명·담당 역할·기술을 배치합니다. Travel Visualizer는 두 시연을 나란히 두고 아래에 설명을 배치합니다.
- 상세 페이지: 구성도와 구현·개선·검증 내용을 같은 그리드와 제목 체계로 연결합니다.
- 목차: 화면 오른쪽 가운데에 작은 플로팅 목차를 둡니다. 전체 프로젝트명을 표시하고, 얇은 세로선과 짧은 강조선으로 현재 위치를 구분합니다. 현재 프로젝트의 세부 페이지 번호를 함께 표시합니다.
- 모바일: 이미지를 먼저 보여 주고 본문을 세로로 배치합니다. 목차는 상단 버튼에서 열며 시연 버튼은 본문 너비로 표시합니다.

## 문체

본문은 명사형과 음·함·됨의 보고서형 표현을 사용하고 문장 끝 마침표는 최소화합니다. 기능·역할·결과를 간결하게 쓰며, 별도의 AI 활용 어필이나 하단 부연 문구를 붙이지 않습니다. 수치의 실험 조건과 팀원 역할처럼 판단에 필요한 정보는 해당 본문에 통합합니다. 실제 사진·화면이 중심이 되도록 반복 설명과 장식성 문구를 줄입니다.

## 웹과 출력

- 웹과 PDF는 같은 1120×630px, 16:9 `.slide`를 사용합니다.
- PDF에서만 글자를 줄이거나 내용을 숨기지 않습니다.
- 모바일에서는 높이를 자동으로 늘려 내용을 모두 표시합니다.
- 16:9 PDF는 16장, A4 세로 인쇄본은 같은 슬라이드를 두 개씩 배치한 8장입니다.
- 폰트 파일은 배포하지 않습니다.
- 스타일과 스크립트를 변경할 때 `docs/index.html`의 자산 버전 쿼리를 갱신합니다. 단일 HTML 생성기는 이 쿼리를 제외한 경로로 자산을 읽습니다.

## 자료 보기

프로젝트 개요의 자료 링크는 설명 열 아래쪽에 두고, 기술 태그와 최소 28px 간격을 둡니다. 모바일에서는 본문 뒤에 24px 간격으로 이어집니다.

프로젝트 첫 페이지의 영상은 화면 안에서 무음·반복 재생합니다. 현재 화면의 영상을 우선 불러오고 다음 프로젝트의 초기 데이터를 미리 준비합니다. 화면 밖이나 다른 탭·인쇄 상태에서는 정지합니다. 영상은 장면 특성에 따라 2~2.5배속 편집하고 캡션 안에 배속을 표시합니다. 영상과 정지 그림의 번호는 각각 순서대로 매깁니다. 영상은 최대 24fps로 제공하며 아래쪽 이미지는 지연 로딩합니다. 기본 재생 컨트롤로 일시정지·탐색·전체 화면을 사용할 수 있습니다. PDF에는 같은 크기의 대표 장면을 표시합니다. 이미지는 확대 창에서 화면 맞춤·원본 크기를 전환하며, 전공 실습 자료는 갤러리로 탐색합니다. 버튼·링크의 키보드 포커스와 Escape 닫기를 유지합니다. 슬라이드 이동 대상의 기본 포커스 테두리는 표시하지 않습니다.

## 슬라이드 탐색 (2026-10-07)

- PC에서는 한 화면에 한 장을 표시하고 휠·방향키로 넘깁니다. 휴대폰 가로 화면(높이 540px 미만)도 한 장씩 표시하며, 상단바를 44px로 줄여 슬라이드 위아래가 모두 보이게 합니다. 세로 화면은 세로 읽기를 유지합니다.
- 원본 1120×630 비율을 유지하며 기존 크기 조절 미리보기의 115%를 기본값으로 사용합니다(원본 아트보드의 최대 126.5%). 화면이 작으면 비율을 유지하며 맞춥니다. 외곽선과 옅은 그림자로 배경과 구분합니다.
- 상단바는 고정하며 바로 아래에 진행선을 둡니다. 상단 페이지 번호와 모션 설정 버튼은 표시하지 않습니다.
- 모션은 기본으로 켭니다. 슬라이드 전환 280ms, 목차 표시 이동 320ms, 진행선 240ms를 사용합니다.
- 넓은 화면의 목차는 슬라이드 오른쪽 76px 간격에 배치합니다. 1700px 미만에서는 상단 목차 버튼으로 엽니다.
- 천천히 휠을 돌리면 한 장씩 280ms로 전환합니다. 빠른 연속 입력은 페이지 맞춤을 잠시 풀어 연속으로 훑어보고, 160ms 동안 입력이 없으면 가까운 슬라이드에 정렬합니다. 빠른 입력도 짧은 보간 애니메이션으로 따라가며, 이동 목표는 현재 위치에서 화면 높이의 75% 이내로 제한합니다. 빠른 입력을 장수로 쌓아 뒤늦게 넘기지 않습니다.
- 하단에는 이메일과 강조된 ‘맨 위로’ 버튼을 둡니다. PDF 저장은 상단 버튼에서 슬라이드형(1장씩, 16:9 16쪽) 또는 A4 인쇄형(2장씩, A4 세로 8쪽)을 고르면 미리 만든 PDF를 내려받습니다.

### 모바일 세로 읽기

- 본문은 16px 수준을 유지하고, 슬라이드 높이는 내용에 따라 늘립니다. 강제 페이지 맞춤과 페이지별 상단 빈 공간은 두지 않습니다.
- 상단바 아래의 여백을 목차 이동에도 적용합니다. 모바일 주소창 등으로 화면 높이가 달라져도 읽던 스크롤 위치를 유지합니다.
- 링크·주요 버튼은 최소 44px 터치 높이를 확보합니다. 420px 이하에서 문제·개선 표는 행별 세로 배치로 읽습니다.

- 700px 이하 세로 읽기에서는 바깥 프레임을 없애고 화면 폭을 활용합니다. 본문 안쪽 여백은 20px이며, 프로젝트 탭과 목차는 충분한 터치 영역을 확보합니다.

### 전체 발표자료

발표 원본이 있는 5개 프로젝트의 설명·기술 태그 아래에 전체 발표자료 버튼을 둡니다. 소스 코드와 동일한 텍스트 링크 스타일을 사용하고, 소스 코드가 있으면 같은 동작 영역에 나란히 배치합니다. 진한 배경·테두리를 두지 않으며 모바일에서도 링크 크기를 유지하되 터치 높이는 44px 이상 확보합니다. 별도 화면에서 현재 슬라이드와 다음 장만 불러오고, 이전·다음·번호 이동·확대·PDF 다운로드·포트폴리오 복귀를 제공합니다. 원본 PPT의 정적 변환본이며 영상과 애니메이션은 정지 화면으로 표시합니다.
